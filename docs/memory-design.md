# FeiyuNote 两层记忆：产品行为与实施规格

更新：2026-10-02。状态：供执行 Agent 实现的设计，尚未改动 Android 源码、执行迁移或验证模型效果。用户明确要求跨项目记忆和项目内记忆，并保留显式整理、控制 token 的原则。

## 1. 参考边界与目标

参考 ChatGPT 的产品思路：跨对话延续偏好和上下文，项目组织相关对话及资料，用户能管理记忆。依据是官方 [Memories](https://learn.chatgpt.com/docs/customization/memories)、[Projects and chats](https://learn.chatgpt.com/docs/projects)、[Personalize ChatGPT](https://learn.chatgpt.com/docs/personalize)。官方这些页面没有披露 ChatGPT 服务端的完整记忆算法；下文的数据表、检索规则、默认值及删除语义均为 **FeiyuNote 自己的设计**。不把文档中的本地 Codex 记忆文件流程等同于 ChatGPT 内部实现。

沿用 Android 本地 SQLite。这里的“全局”指当前 FeiyuNote 本地资料库内的全部课程，不代表自动同步到别人的设备，也不与开发工具 Antigravity 的 Google 登录绑定。未来如果增加多用户账号，再以 account_id 做第一层隔离。

## 2. 两层记忆与开关

| 层级 | 保存什么 | 示例 | 在哪里生效 |
| --- | --- | --- | --- |
| 全局记忆 GLOBAL | 用户明确保存的学习偏好、通用方法，以及从课程主动共享的知识摘要 | 喜欢先讲直觉再讲证明；已复习过特征值定义；线性代数中的正交投影方法 | 开启“全局＋本项目”的课程或刷题本 |
| 项目记忆 PROJECT | 当前课程/刷题本的定义与符号、教师约定、课程重难点、个人疑难点、学习进度、单课学习偏好、带条件的知识摘要 | 本课程内积对第一变量线性；老师强调一致收敛；我对交换极限条件仍有疑问 | 当前 notebook_id 内的不同课次和分支 |

课程项目复用现有 Notebook ID；刷题本也拥有自己的项目记忆。linkedCourseId 只表示关联，不自动授权读取关联课程的项目记忆。用户仍可通过现有入口明确选用关联课程参考笔记；“参考材料”与“记忆”分别展示。

每个项目提供三选一：`OFF`（不使用记忆）、`PROJECT_ONLY`（仅本项目）、`GLOBAL_AND_PROJECT`（全局＋本项目）。全局设置提供“允许使用记忆”总开关；总开关关闭时所有请求均不注入记忆，但管理页仍可编辑已有条目。

新建项目默认“全局＋本项目”，创建页显示选择；旧项目迁移后默认“仅本项目”，不自动扩大旧课程数据的使用范围。全局库初始为空，首次启用需显示说明。关闭使用不等于删除，不在后台补做摘要。

单次提问另有“本次不使用记忆”：这次不读记忆，产生的问答标记为不参加以后记忆提取；原聊天照常保存。以后若用户主动将其中一条“记住”，明确提示这是新的手动保存操作。本功能不要命名为“无痕聊天”，因为它仍保存聊天。

## 3. 学生实际怎么操作

### 3.1 新增一条记忆：无需模型

1. 在回答、笔记或课程资料上选中文字，点“记住”；也可以在记忆管理页点“新增”。
2. 弹出编辑框：内容、类别、主题/关键词、适用范围。课程中发起时默认“本项目”，全局管理页发起时默认“全局”。
3. 用户可改写内容和适用条件，检查来源。明确选择“所有项目可用”才写入全局库。
4. 点保存后本地事务写入，提示“已保存到线性代数”或“已保存到全局记忆”。无额外模型请求。

类别先用 `preference / convention / knowledge / focus / progress / open_question`。focus 再区分教师强调的重点、课程难点、个人疑难点，保留谁标记及哪段材料支持；AI 建议不能冒充教师声明。学习进度是用户确认的当前状态；不能仅凭问了一次问题就永久标记“基础薄弱”。知识条目必须保留结论成立的条件；图片不清楚的识别结果应先澄清。

学习偏好分别支持讲解顺序（直觉/定义/推导）、证明细度、示例形式、篇幅及复习格式。全局保存通用偏好，项目可覆盖同一 preference key；例如通用偏好是先举例，数学分析这门课偏好先写完整定义。只有用户明确选择或确认的偏好才持久化，不能根据提问次数猜测学习能力或偏好。

### 3.2 整理课程记忆：显式调用模型

1. 课程页点“整理并更新记忆”，勾选课次或笔记。默认只选当前课次已完成的文字问答；失败/取消条目和标记不参与提取的条目排除。
2. 展示将发送的材料范围和现有相关记忆；照片默认不附带，需要用户明确选择。
3. 点“生成候选”才调用现有模型入口。一次操作一个请求；超出上下文预算则提示缩小范围或由用户确认分批，不偷偷发多轮。
4. 返回候选卡片，逐条显示“新增 / 建议替换 / 冲突待确认”、内容、来源和范围。默认写本项目；模型建议的 global 字段不能决定实际写入范围。
5. 学生勾选、修改后保存；未选条目丢弃。取消、网络失败、格式错误均不改变已保存记忆。候选不是可检索记忆。

“整理本课 QA”和“整理并更新记忆”是两个独立动作。生成 QA 不连带再生成记忆；可从生成后的 QA 页面主动进入记忆整理。

提取输出结构示意（来源必须是本次允许的 Entry ID）：

```json
{
  "candidates": [{
    "category": "convention",
    "topicKey": "inner-product.linearity",
    "content": "本课程内积约定为对第一变量线性。",
    "keywords": ["内积", "线性"],
    "sourceEntryIds": [101, 104],
    "operation": "add",
    "targetMemoryId": null,
    "expectedVersion": null
  }]
}
```

模型只提出建议。应用验证字段、长度、枚举、来源可见性和目标版本；不接受模型给出的 SQL、项目 ID 或任意工具调用。无来源的用户手动新增标记为“用户自述”；模型提取必须有有效来源。确认保存表示用户选择采用，不表示数学真实性已由程序证明。

### 3.3 跨课程使用

在线性代数里选中“正交投影”记忆 → “共享到全局” → 编辑为独立可理解且保留条件的摘要 → 查看对所有启用全局记忆的项目可见 → 保存。概率论里提到“最小二乘”时，可检索到这条全局摘要，显示“来自线性代数”的可回查来源。

全局共享生成独立条目，记录来源记忆 ID 与版本。之后课程原记忆变更，全局副本标记“来源已变更，待复核”，不静默同步。项目教师约定不应自动上升为所有学科的通用事实。

“跨课程串讲”是另一个显式动作：学生勾选课程及笔记，展示材料范围，再请求综合讲解。可选材料仅对此次请求授权，不把其他课程原始聊天永久加入全局，也不因串讲自动保存新记忆。

### 3.4 查询、纠错、暂停和删除

- 设置 → 记忆管理：全局/项目标签、搜索、类别筛选；每项可编辑、暂停、删除、查看来源。课程页直接进入本项目标签。
- 回答下方“本次参考的记忆”：展示注入了哪些条目及来源，并提供“纠正这条记忆”。这只是输入记录，不能声称模型确实依赖每一条作答。
- 修改采用版本校验；发现别人/另一个界面刚改过同一条时，展示差异，不以旧版本覆盖。相同 topicKey 的矛盾内容要求用户选择替换、分别注明适用条件或取消。
- “暂停”保留内容但不参与检索；“删除”移除条目正文、关键词和来源关系，清理相关候选及缓存。派生全局副本默认同时删；删除界面列出影响范围，也允许用户明确保留副本。
- 删除原聊天/课程前展示相关记忆数，默认连同由其派生的记忆删除；若用户选择保留，来源标记已删除、记忆转为待复核，复核前不注入。多来源条目需用户重审剩余证据，不能假定剩余来源足以支撑原结论。
- 删除记忆不会删除原聊天或过去生成的回答；界面必须说明。需要一并删除时提供明确跳转/选项。已发送给模型的上下文不能由本地删除操作追溯撤回。

### 3.5 “整理本课”生成个性化复习资料

这是用户后续明确补充的需求：本课复习资料应结合前面的学习内容、课程重难点与学习偏好，突出反复提问的内容。以下替代仅把本课问答压缩成 QA 的初步方案。

**输入如何组成：**

1. 学生点“整理本课”，先看到范围：本课所有已完成问答及分支、所选笔记；可取消某些条目。未完成/失败回答不作为知识依据。
2. 根据本课主题检索本项目之前保存的重难点、未解决问题与相关知识记忆，受当前模式和预算约束；显示“关联前课内容”清单并可取消。当前需求不意味着自动发送所有前课原始聊天。
3. 允许全局记忆时读取相关学习偏好；本项目偏好覆盖同键全局偏好。全局知识或其他课程材料只有在范围面板明确勾选才加入本课复习资料，并标为“延伸联系”。
4. 应用本地计算本课提问分布，将有来源的统计与学生标记一同发送。统计本身不调用模型；整理资料仍复用原 SUMMARY 的一次调用。
5. 模型生成复习资料草稿；保存为 NOTE，并记录来源、使用的记忆版本、统计范围和时间。可以之后明确执行“更新记忆”，但生成资料不自动再调用摘要服务或改学习档案。

**提问统计的具体规则：**

- 最小计数单位是持久化的用户 Entry。区分主动 ASK、追问 ASK、按钮 EXPAND，分别计数；响应重试、模型自己写的问句、重复打开界面不增加提问数。统计每个知识点的涉及问答数、追问数、涉及独立根问题数与最近一次提问时间。
- 首先用用户设置的主题标签、已确认记忆关键词和同一父链归组。无法可靠归类时保留“分支主题待整理”，不要凭字符串命中断言两个同名概念相同。
- SUMMARY 可在同一次响应中建议 `topic → sourceEntryIds` 的知识点归组。应用检查 ID 属于本次统计范围，去重后重新计算次数；模型生成的任意次数不能直接显示。最终数量由应用渲染，正文不接受未经验证的数字。
- 默认将涉及至少 2 个独立根问题，或出现至少 3 次用户追问/展开的主题标记为“关注较多”。这是可调的产品启发式，未校准概率，不是“不会”的判定。次数少但用户明确标记不理解的条目仍需优先复习。
- 每次显示原因，例如“本课 2 个独立问题涉及此概念，另有 3 次追问；建议确认是否已掌握”。同时允许“仍不理解 / 已理解 / 只是感兴趣”三种反馈。后两者取消自动的个人薄弱点优先级，但不抹去客观次数和课程重点标记。
- 反馈更新的是该项目该主题的学习状态，默认不共享到全局。学生主动标记可直接本地保存；AI 根据统计提出的疑难点必须经确认才成为持久记忆。时间久远的未解决项提示复核，不能无限视为当前困难。

**输出固定为可复习的结构：**

| 部分 | 内容及依据 |
| --- | --- |
| 本课知识脉络 | 主要概念、前提、结论及与已选前课内容的关系，区分本课与前课来源 |
| 课程重难点 | 教师强调/用户标记/AI 建议分别标识；重要不等于难，难不等于本人不会 |
| 关键例题与证明 | 按学习偏好安排直觉、步骤、条件、易错点；不因偏好简洁省略必要条件 |
| 精选 QA | 合并重复但保留不同疑问与逐条来源；不能只留下结论 |
| 建议优先复习 | 明确未解决的问题优先，再列关注较多且未标记已理解的主题；附提问证据和具体复习建议 |
| 前课联系与未解决项 | 标明前课来源、冲突/缺失资料以及还需向老师确认的问题 |

优先级以“明确未理解 → 高频且未确认理解 → 其余课程重难点”为建议排序，不给未经校准的掌握分数。某个主题标记“已理解”后，仍可作为课程重点保留在知识脉络中，不再反复被称为个人薄弱点。

## 4. 存储与迁移：复用现有 SQLite

最新 fork 快照 `bc33554b294a37ff62df5ba04d911d8d68157224` 中 `NotebookDatabase.VERSION=3`，v2→v3 已用于 templates.source 和引导模板。实现前读取真实 checkout，若仍为 v3，追加非破坏性的 v3→v4；如果已变化，以当前版本递增。保留已有 v1/v2 升级链，验证旧库连续升级和当前 v3 升级；不能重用版本 3 或重复播种用户已经删除的引导模板。不能删库重建，也不随功能引入 Room 或云端服务。

建议实体（字段命名可适应项目风格，但行为约束不可省略）：

| 实体 | 关键字段与约束 |
| --- | --- |
| memory_items | id、scope、notebook_id、category、topic_key、content、keywords_json、state(active/paused/needs_review)、pinned、version、created_at、updated_at、review_after；GLOBAL 的 notebook_id 必须为空，PROJECT 必须指向当前存在的 Notebook |
| memory_sources | memory_id、source_type(entry/memory/manual)、source_id、source_version 或内容哈希、source_state；不复制整个聊天/照片；原条目已删除时可标注失效 |
| project_memory_settings | notebook_id 主键、mode；Notebook 删除时级联删除 |
| request_memory_refs | response_entry_id、memory_id、memory_version、scope；只记实际发送的条目引用，不复制正文；记忆删除后显示“已删除” |
| memory_suppressions | scope_key、topic_key_hash、source_id、content_hash、created_at；阻止已明确丢弃/删除的同源同内容候选马上再次出现，不保存被删正文 |

补充结构：focus 条目具有 `focus_kind`（teacher_important/course_difficult/personal_uncertain）和 `marked_by`（user/teacher_source/ai_suggestion）；teacher_source 必须有材料依据。项目学习状态保存 topic_key、status(unclear/understood/interest_only)、confirmed_at 和来源。可作为 progress 条目的结构化附加字段，避免维护第二份矛盾状态。SUMMARY 的统计快照保存各主题涉及的去重 Entry ID 及时间范围；不必每次提问调用模型或重新生成记忆。Entry 的主题标签可单独用 `entry_topic_tags` 关系表，人工标签与模型建议需可区分。

全局总开关沿用应用当前设置存储。Entry 增加 `memory_eligible` 布尔字段供本次不记忆使用，新建普通条目为 true；不修改原 parentEntryId、sourceEntryIds 语义。记录删除/编辑导致的 `memoryRevision`，用于让准备中的请求重新校验。

数据库 CHECK 示例：

```sql
CHECK ((scope = 'global' AND notebook_id IS NULL)
    OR (scope = 'project' AND notebook_id IS NOT NULL))
```

索引：`(scope, notebook_id, state)`；topic_key 的唯一性只在同一作用域内生效。全局使用独立部分唯一索引，项目使用 `(notebook_id, topic_key)` 部分唯一索引，避免 SQLite 的 NULL 让全局重复漏检。不同条件的知识可以用不同 topic_key，并在正文保留条件。

新增/替换条目、来源变更、更新版本与关联失效标记放同一事务。DAO 采用参数绑定；scope 和 notebook_id 由应用导航/请求上下文确定，不从模型文本解析。共享到全局使用单独 Repository 方法，必须收到界面明确选定的目标范围。

删除抑制规则只保证同源/同内容不立即重提；它不是语义上的永久遗忘。所有重新生成候选仍需用户确认才能入库；用户主动重新保存可显示提示后解除相应抑制记录。不要夸大哈希去重的能力。

迁移只增加结构和默认设置，不在迁移中调用网络、生成摘要或把历史聊天批量搬进记忆。数据库约束、级联删除和版本冲突需要真实 SQLite 测试，不能只测内存假对象。

## 5. 检索和上下文装配：由应用执行

### 5.1 硬性范围过滤

```text
resolveMemory(request):
  if !globalUseEnabled or request.skipMemory or project.mode == OFF:
      return []
  allowed = 当前 notebook 的 active 项目记忆
  if project.mode == GLOBAL_AND_PROJECT:
      allowed += active 全局记忆
  allowed -= 过复核时间、来源变更/删除、待复核的条目
  return rankAndBudget(allowed, request)
```

必须先在查询层限定作用域，再评分。不能先搜索全库、取前 N 条后才靠提示词让模型“不要使用其他课程”。课程重命名不改变 ID；linkedCourseId 不扩大 allowed。

### 5.2 第一版的具体检索算法

1. 查询文本取当前问题、选中概念、课次标题和当前祖先链最近一条用户问题；不拼全部历史或兄弟分支。
2. 规范化大小写与空白；关键词取用户标签、英文词和中文连续二字片段。先用范围索引过滤，再参数化 LIKE/关键词匹配检索；转义 `%`、`_`。首版无需向量数据库或额外 embedding 请求。
3. 最多取 100 条相关候选，固定排序：同 topicKey 的本项目条目覆盖全局默认；其次手动置顶、关键词命中数、更新时间，最后 id 保证稳定。关键词零命中时，仅允许短的偏好/课程约定，不把无关知识补满预算。
4. 第一版可配置默认：单条最多 1,024 UTF-8 字节、最多 12 条；序列化后全局段 ≤2 KiB、项目段 ≤6 KiB、总记忆段 ≤8 KiB。数字是工程起始参数，未做效果/性能测量。超限整条舍弃，不切断定理条件或公式；置顶也必须服从上限。
5. 字节上限不是精确 token 数。若供应商有准确 tokenizer/用量，单独记录；否则 UI 标为估算或仅显示字符/字节数。完整请求仍需要模型容量预算和输出余量。

这套本地检索只缩减输入，不新增模型调用；命中效果需用课堂样例评估。若中文同义词召回不足，先补关键词；以后有证据再考虑语义检索。

### 5.3 接入现有请求流程

ContextBuilder 保留动作指令、用户明确选的参考材料、当前祖先链和当前问题。加入独立的“个人学习背景/课程背景”数据段，带 scope、id、version 和来源标签；不把记忆正文提升为系统指令。条目中的“忽略规则/读取别的项目”等文本不能改变应用权限或生成工具调用。

当前用户明确要求优先于记忆中的旧偏好；本课符号约定优先于全局默认。对于数学结论冲突，列出条件和来源差异，不能仅以“本课优先”掩盖错误。

准备请求时固定 memory id+version 快照；发送前复查全局/项目开关、条目状态及 memoryRevision。删除或切换范围后取消尚未发送的旧请求并重新构建，避免旧缓存继续使用。已发出的请求支持尽力取消，但不能声称服务端未收到。

总上下文超限时先删除低相关记忆，其次提示用户减少参考材料/选择分段。当前问题、题目条件和明确选中的图片不能被静默截去。课后 QA 按第 3.5 节组合本课原材料、相关前课记忆、重难点、学习偏好和可核查的提问统计，生成前显示范围；其他课程原材料或全局知识扩展须明确选择，不能伪装成老师本课讲过的内容。

## 7. 实施顺序与验收

先完成规划包中的 `antigravity-first-task.md` 基线任务，再执行 `antigravity-memory-task.md` 功能任务。容器内二者位于只读的 `/opt/feiyu-planning/outputs/`；本规格可单独安装到应用 `docs/memory-design.md`。按以下顺序交付，避免把侧边追问、学科分类和记忆同时重构：

1. **M1 存储和手动管理**：迁移、两个作用域、CRUD、来源、开关、跨项目显式共享。无模型也能使用和验证。
2. **M2 在回答中使用记忆**：Retriever、ContextBuilder、预算、输入记录、请求失效处理。使用假模型检查实际发送内容。
3. **M3 显式整理候选**：选择课次→生成→校验→确认；补冲突、取消、错误和来源变化路径。
4. **M4 个性化复习资料**：课程重难点与项目偏好、基于来源的提问统计、复习资料范围确认、建议优先复习及学生纠正入口。复用 SUMMARY 单次调用，不默默多发模型请求。

验收必须包含：

| 场景 | 通过条件 |
| --- | --- |
| A/B 两门课程与全局 G | A 问题不会读 B 项目条目；全局 G 仅在允许全局时出现；切换 OFF 后全不出现 |
| 共享与关联刷题本 | A 的指定摘要提升到 G 后 B 可用；未共享原文及 linkedCourseId 下课程记忆仍不会自动进入 |
| 普通提问/整理 QA | 各自只发原本应有的一个生成请求，不附加记忆摘要调用；单纯读取/打开侧栏零请求 |
| 明确整理记忆 | 只有点击生成才请求；候选确认前零数据库记忆变更；非法来源/范围/JSON 不落库 |
| v1/v2 连续升级、v3 升级及重启 | 原 Notebook/Lesson/Entry、图片引用和父链保留；新增模式和记忆可重启读回；迁移失败不会删旧库 |
| 当前分支 | 兄弟分支不进入上下文；用户显式保存的项目摘要可跨分支复用，标签显示其为记忆 |
| 编辑/删除/取消 | 旧版本不能覆盖新版本；删除影响派生项；发送前删除不发送旧快照；失败不误写已保存状态 |
| 来源变化 | 原条目变动或删除后记忆转待复核；界面可定位有效来源或准确显示失效 |
| 长文本与公式 | 序列化记忆段不超上限；公式/条件整条保留或整条排除；当前问题不被截断 |
| 恶意记忆文本 | 不能扩大 scope、修改请求规则或直接执行工具；只作为带边界的数据 |
| 重难点与偏好 | 教师重点有来源、个人疑难点有确认依据；项目偏好覆盖同键全局偏好；简洁偏好不删必要条件 |
| 高频与反例 | 多次提问被提示复习；“只是感兴趣/已理解”取消薄弱点推断；一次明确不理解仍会优先出现 |
| 统计真实性 | 重试/展开界面不增加计数；ASK 与 EXPAND 分开；模型虚构 ID/重复 ID 被拒绝或去重；次数由程序重算 |
| 复习范围与成本 | 本课、前课记忆、全局延伸来源可区分；生成复习资料只有一次 SUMMARY 调用，不附带记忆刷新 |

运行项目既有单测和 debug APK 构建；数据库测试按仓库现有设施执行。需要 Android 设备的迁移/界面测试若当前无设备，应如实记为未执行，不以 JVM 假仓库测试替代。真实数学讲解质量、照片识别、token 节省属于后续人工试用/测量。

## 8. 首次演示用例

创建“线性代数”“概率论”两个项目 → 保存全局偏好“先直觉后推导” → 在线性代数保存本课符号约定 → 两课分别提问并查看注入记录 → 将投影知识摘要共享到全局 → 概率论选“全局＋本项目”提问最小二乘 → 改成“仅本项目”再对比 → 删除共享条目并确认下一次请求不再注入 → 选一节课显式生成候选，取消一次、确认一次 → 关闭并重开应用核查持久化。

这组演示先用假模型验证数据流；接真实模型时另外记录所用模型及实际输出，不提前宣称教学效果提高。

## 最新 fork 的兼容约束

用户可编辑 STUDY、GENERAL、SUMMARY 系统提示词，模板和文本 Skill 也参与请求。接入记忆时保留已有设置和覆盖入口；检索作用域、预算、来源 ID 校验、统计重算和记忆写入权限必须由代码保证，用户修改提示词不能绕过这些条件。增加自定义 SUMMARY 提示词与记忆同时启用的回归验证。外部 SKILL.md 是应用中的文本素材，不能执行其中命令或把它作为开发 Agent 指令。没有课程归属的普通聊天不能默认选取任意课程记忆；首版明确课程入口范围，未定义入口保持现状并记录。
